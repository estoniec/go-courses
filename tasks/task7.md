### Docker + Kubernetes

Разверните приложение из ДЗ 6 в Docker Compose и локальном Kubernetes. На этом этапе проект состоит из одного приложения `catalog-service`. Оно скачивает фильмы со стенда, хранит их в PostgreSQL и использует Redis для индекса и кэша.

### Данные и API

Фильм-стенд [kinosearch](https://github.com/vacmannnn/kinosearch) возвращает по `GET /{id}/info.0.json` только четыре поля:

```json
{"id": 1, "title": "Solaris", "year": 1972, "director": "Andrei Tarkovsky"}
```

`id` и `year` — числа, `title` и `director` — строки. Для отсутствующего фильма стенд возвращает 404. Описание, актёры и жанры не требуются; получать их из других источников не нужно. Поиск остаётся по словам из названия и режиссёра.

Пользовательские HTTP/gRPC API сохраняют контракт предыдущих ДЗ. Для HTTP обязательны `/load-movies?from=N&to=M` (JSON-массив), `/last-movie` (JSON-объект) и `/search?q=...` (JSON-массив, при отсутствии совпадений — `[]`). Все фильмы содержат `id`, `title`, `year`, `director`.

### Docker Compose

- Напишите `Dockerfile` для приложения.
- Добавьте Compose-файл, который собирает приложение и запускает его вместе с PostgreSQL и Redis. Для зависимостей используйте образы PostgreSQL и Redis.
- Весь проект должен запускаться одной командой `docker compose up --build`. При старте приложение применяет SQL-миграции до синхронизации каталога.

Положите один файл `compose.yaml`, `compose.yml`, `docker-compose.yml` или `docker-compose.yaml` в корень решения ДЗ 7. Имя сервиса приложения должно содержать `catalog`, например `catalog-service`. Собирайте образ приложения через `build` и опубликуйте его HTTP-порт.

Сохраняются переменные окружения из предыдущих ДЗ: `MOVIE_BASE_URL`, `HTTP_ADDR`, `DATABASE_URL`, `REDIS_ADDR`. В DSN и адресе Redis используйте сетевые имена сервисов Compose. Передайте `MOVIE_BASE_URL` в окружение контейнера и предусмотрите возможность переопределить его при запуске. Приложение запускается без обязательных CLI-аргументов.

### Kubernetes

- Добавьте `Deployment` и `Service` для приложения. Имя Deployment должно содержать `catalog`. Селекторы Deployment и Service должны выбирать pod'ы приложения.
- Вынесите настройки в `ConfigMap`, а чувствительные значения — в `Secret`. Подключите их к Deployment.
- Настройте readiness/liveness probes и задайте CPU и память в resource requests и limits.
- Укажите `replicas: 2` или больше, запустите проект в локальном кластере и проверьте обычный запрос к API при готовых репликах.

PostgreSQL и Redis можно поднять в кластере простыми манифестами или подключить готовые экземпляры. Манифесты можно хранить в каталоге `k8s/` в виде обычных YAML-файлов.

В README опишите запуск и остановку Compose, адрес API и переменные окружения. Добавьте команды применения Kubernetes-манифестов и изменения числа реплик, а также пример успешного запроса при двух готовых репликах.

### Критерии оценивания

6 баллов — Dockerfile собирает приложение. Docker Compose одной командой поднимает каталог, PostgreSQL и Redis, HTTP-порт опубликован, MOVIE_BASE_URL можно переопределить через окружение. Сохранены API и поиск по названию и режиссёру на данных из четырёх полей. В Kubernetes для каталога есть Deployment и Service, используются ConfigMap и Secret, настроены readiness/liveness probes и resource requests/limits. Проверен обычный запрос к API при нескольких репликах catalog-service. В README описаны запуск через Compose и Kubernetes и изменение числа реплик.

5 баллов — Запуск через Compose и Kubernetes работает, все обязательные манифесты и настройки добавлены, несколько реплик обслуживают запросы. Есть небольшой недочёт в документации, например, не приведена команда изменения числа реплик.

4 балла — Приложение и зависимости запускаются через Compose, базовое развёртывание в Kubernetes работает, но отсутствуют probes, resource requests/limits или проверка нескольких реплик. Либо конфигурация не полностью вынесена в ConfigMap/Secret или нельзя переопределить MOVIE_BASE_URL.

3 балла — Работает только один способ запуска: Compose или Kubernetes. Либо Docker-образ собирается, но для запуска всей системы нужны неописанные ручные шаги, часть зависимостей отсутствует или API недоступен снаружи Compose.

0–2 балла — Работа не сдана, Docker-образ не собирается или приложение нельзя запустить ни через Compose, ни через Kubernetes. Либо конфигурационные файлы добавлены формально и не позволяют запустить приложение.

Отметка за задание снижается при более поздней сдаче задания (1 балл за каждые 2 недели опоздания).
